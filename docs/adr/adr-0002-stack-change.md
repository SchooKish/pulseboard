# ADR-0002: Stack change

## Context

В ходе обсуждения архитектуры проекта возник вопрос,
нужен ли отдельный backend-сервис.

Первоначально предполагалось использовать связку Nuxt + NestJS,
однако после анализа требований MVP стало очевидно,
что большая часть логики представляет собой CRUD, агрегацию данных и работу с внешними API.

Необходимо выбрать архитектуру,
которая позволит быстрее реализовать MVP, 
сохранив возможность дальнейшего масштабирования.

## Options

* Ничего не менять
* Оставить в качестве бэкэнда Nest, а на фронте использовать связку tRPC + vite
* Остановиться на Nuxt - делать Fullstack приложение

## Decision

Для MVP выбран Nuxt Fullstack (Nitro).

Причины:

* серверная логика пока относительно проста;
* frontend и backend развиваются одной командой;
* общие типы без генерации;
* меньше инфраструктуры;
* более высокая скорость разработки.

Отдельный backend будет рассматриваться только при появлении объективных ограничений.

## Consequences 

### Positive
* меньше инфраструктуры
* меньше DevOps
* меньше boilerplate
* единые типы

### Negative
* более сильная связанность frontend/backend
* сложнее масштабировать независимо API
* придётся самостоятельно определить архитектурные правила
* часть возможностей Nest отсутствует "из коробки"


Nest требует от разработчика писать в определённой архитектуре, 
у Nuxt же такого нет → мне нужно разобраться в архитектуре Nuxt Fullstack приложения
